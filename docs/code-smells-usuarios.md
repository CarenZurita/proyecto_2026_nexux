# Auditoría de code smells del módulo Usuarios

## Alcance y metodología

La auditoría se limita al módulo Usuarios y a sus vistas, controladores, servicios y persistencia. Se usó el catálogo [Code Smells de SourceMaking](https://sourcemaking.com/refactoring/smells) y no se usaron categorías fuera de esa página.

No se modificó código ni se ejecutó la aplicación.

## Verificación específica de hipótesis

1. **`UsuarioService` como Middle Man: se confirma parcialmente.** [UsuarioService.java](../src/service/UsuarioService.java): **L17** `public List<FichaUsuario> listar(Usuario sesion) throws IOException {` delega a **L18** `        return gestionUsuariosService.listarUsuarios(sesion);`. `guardar` solo decide entre registrar y actualizar, por lo que aporta una API de aplicación y no es un shell totalmente vacío.
2. **`GestorUsuarios` como Middle Man/Duplicate Code: fue Middle Man, no Duplicate Code; se resolvió en 2e-B.** La clase facade se eliminó después de migrar las pruebas a servicios; no se encontró una copia de las implementaciones de los servicios.
3. **Mutaciones públicas de `Usuario`: no confirman Inappropriate Intimacy ni Data Class.** [Usuario.java](../src/model/Usuario.java): **L405** `public void setNombreCompleto(String nombre) {` y **L416** `public void setActivo(boolean activo) {`. La clase tiene comportamiento real de autenticación y recuperación. Los mutadores son públicos por autorización previa, pero no se encontró acceso directo a campos internos.
4. **Código de consola/comentarios: código de consola eliminado, comentario obsoleto pendiente.** En esta auditoría no quedó código de consola de gestión de usuarios en `src/model/GestorUsuarios.java` o `Administrador.java`; por tanto, el Dead Code de esa ruta está resuelto. [Usuario.java](../src/model/Usuario.java): **L135** contiene el comentario obsoleto señalado arriba.
5. **Dependencias hacia repositorios de medicamentos/ventas: Divergent Change, no Inappropriate Intimacy por sí solas.** [Administrador.java](../src/model/Administrador.java): **L15** `public void registrarMedicamento(Medicamento medicamento,` recibe **L16** `                                     MedicamentoRepository medicamentos`; **L50** `public List<Venta> consultarHistorialVentas(VentaRepository ventas) throws IOException {`. [Encargado.java](../src/model/Encargado.java): **L15** inicia `buscarMedicamento` y **L30** inicia `registrarVenta`; las operaciones usan APIs públicas del repositorio, no campos internos. Con `Usuario`, sí forman una responsabilidad cruzada que merece Extract Class.

## Estado y deuda pendiente

- **Resuelto en 2a–2d:** autenticación, recuperación y gestión se separaron en servicios; la composición Swing usa inyección y `FichaUsuario` se trasladó a `model`.
- **Resuelto en 2e-A:** se eliminó el código de consola muerto de gestión de usuarios.
- **Resuelto en 2e-B:** se retiró el facade aprobado y se corrigió el comentario de [Usuario.java](../src/model/Usuario.java):135.
- **Pendiente antes del módulo 8:** descomponer `Usuario.desdeLinea` mediante Extract Method sin modificar el formato TXT. Mantener `UsuarioTest` y las pruebas de `UsuarioRepository` como red.
- **Módulo 6:** sacar las operaciones de medicamentos de `Usuario`, `Administrador` y `Encargado` mediante Extract Class.
- **Módulo 7:** sacar el registro de ventas y su actualización de inventario mediante Extract Class.
- **Módulo 8:** separar persistencia TXT y descomponer el parser sin cambiar formatos.
- **Aceptados sin cambio:** parámetros largos, Data Clumps de credenciales `char[]`, `UsuarioService` como frontera y `FichaUsuario` como DTO.
- **Transversal fuera de alcance:** tamaño de menús y tarjetas duplicadas.
